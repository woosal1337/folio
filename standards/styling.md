# Styling Standards

Tailwind CSS + shadcn/ui (style: "new-york", baseColor: "neutral"). Design
tokens are CSS variables; Tailwind reads them via `hsl(var(--name))`.

## Token-first

- Colours live as HSL component triples in `src/styles/globals.css`. Light
  is the default; dark is applied via `[data-theme="dark"]` on `<html>`.
- Add a new colour by adding a `--name` token in *both* themes, then a
  Tailwind alias in `tailwind.config.ts`. Components reference the
  Tailwind name (`bg-primary`), not the variable directly.
- `--radius` controls border radius scale. `xl`, `lg`, `md`, `sm` are
  derived in the Tailwind config. Don't introduce new radius values
  without checking if the scale already covers it.

## Palette intent

The palette is sage-on-cream in light mode, deep neutral in dark.

- **Surfaces:** `background` (page), `card` (raised surfaces),
  `popover` (overlays), `sidebar` (left rail). Each has a matching
  `*-foreground` for legible text.
- **Primary:** sage green (`165 42% 30%`). Used for the main action,
  recording button when armed, selected state borders.
- **Secondary:** muted neutral. Used for resting buttons, tab strips,
  the scrub track.
- **Accent:** lighter sage tint. Used for selected list items and
  hover surfaces. `accent-foreground` is the readable foreground on
  accent.
- **Destructive:** red. Reserved for destructive actions and the
  recording indicator pulse.
- **Muted:** soft neutral surface. `muted-foreground` is the secondary
  text colour.

Do not introduce a new semantic colour without naming it in the design
tokens. Avoid raw hex values in components.

## Typography

- Sans: Inter (loaded from `@fontsource/inter`).
- Serif: Spectral. Used for screen headings (`font-serif`).
- Mono: JetBrains Mono. Used for code, paths, timestamps, durations.
- Font features `cv02, cv03, cv04, cv11, ss01` are enabled on `body`
  to use Inter's stylistic alternates.

## Components

- `src/components/ui/*` are shadcn primitives. Generated by
  `pnpm dlx shadcn add`. We modify them when the design needs it; the
  diff is checked in.
- Feature components in `src/components/` compose primitives. They are
  the only place that contains domain-specific layout logic.
- Routes (`src/routes/`) assemble feature components into screens. They
  may contain layout-specific Tailwind but should not redefine primitives.

## Variants

- `class-variance-authority` (`cva`) for variant-based component styling.
  Variants and sizes are defined in one block; defaults are explicit.
- New variants get a name that reflects intent (`size="xl"`, not
  `size="extraLarge"`). Stick to T-shirt sizes: `sm`, `default`, `lg`,
  `xl`, plus `icon` for square icon buttons.

## Composition utilities

- `cn(...)` from `src/lib/utils.ts` is the only class composer. It
  applies `clsx` for conditional classes, then `twMerge` to resolve
  conflicting Tailwind utilities (the last wins).
- Don't hand-resolve conflicts (`p-2 ${x ? "p-4" : ""}` works but is
  brittle). `cn("p-2", x && "p-4")` does the right thing.

## Dark mode

- `darkMode: ["class", '[data-theme="dark"]']` so the dark variant
  applies when `[data-theme="dark"]` is set on `<html>`.
- `applyInitialTheme()` reads localStorage and applies the theme before
  React mounts. This avoids the wrong-theme flash on first paint.
- All shadcn primitives read tokens that change between themes; no
  per-component dark branching should be needed.

## Spacing

- Use Tailwind's default scale (`gap-1`, `gap-2`, ...). Arbitrary
  values (`gap-[7px]`) are a last resort.
- Vertical rhythm: `gap-y-2` for tight groups, `gap-y-4` for related
  sections, `gap-y-6+` for visual separation.
- Padding for cards: `p-6` body, `pt-0` after a header. Padding for
  rails: `p-3` to `p-4` is the range.

## Borders and shadows

- Borders are `border-border` (token-driven). Don't hard-code `border-zinc-200`.
- Cards use `shadow-sm` by default. Modals use `shadow-xl`. Inline
  inputs use `shadow-sm`. Hover states do not add shadow; they shift
  the background colour.
- Border radius: `rounded-md` for inputs/buttons, `rounded-lg` for
  larger surfaces, `rounded-xl` for cards, `rounded-2xl` for the
  Settings dialog and other modals.

## Animation

- `tailwindcss-animate` plugin is enabled.
- Custom keyframes (`pulse-record`, `accordion-down`, `accordion-up`)
  live in `tailwind.config.ts`. Adding a new animation requires a
  matching `animation: { ... }` entry.
- Durations: `0.2s` for utility motion (hover, accordion);
  `1.4s` for the recording pulse (intentionally calm).
- Respect `prefers-reduced-motion`. Components that animate should
  degrade gracefully; add a `motion-reduce:transition-none` utility
  for now and revisit when we own more than two custom keyframes.

## States

- Hover: bump the background lightness or shift to a related surface
  token. Never just darken with `opacity`.
- Focus: `focus-visible:outline-none focus-visible:ring-2
  focus-visible:ring-ring focus-visible:ring-offset-2`. Standard for
  every interactive element.
- Disabled: `disabled:pointer-events-none disabled:opacity-50`. Apply
  on the element, not the parent.

## Drag affordance

- Window drag regions are `data-drag=""` divs. macOS overlays the
  traffic lights on top automatically; the `[data-drag]` selector
  excludes interactive children (`button, a, input, ...`).
- The `drag` and `no-drag` utility classes in `globals.css` expose the
  WebKit `-webkit-app-region` properties for use cases where the
  data-attribute path is insufficient.

## Don'ts

- No `!important`. If a class is being overridden, the cause is class
  ordering, not specificity.
- No inline `style={}` for anything other than dynamic numeric values
  (percentages, scroll offsets). Tokens belong in Tailwind classes.
- No global CSS rules outside `globals.css` and the `@layer` blocks.
  Component-scoped CSS lives in Tailwind utilities.
